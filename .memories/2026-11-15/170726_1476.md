## E2E_REAL=1 real-source mode + live-catchup.lua fix

- **What:** opt-in real-provider run in the VM e2e (`E2E_REAL=1`, `E2E_REAL_LIVE/VOD` name substrings). `vm_seed --real <file>` reads the URL file itself (detect + add_source), `vm_seed --wait` polls the first refresh, `scripts/vm/redact.py` scrubs/scans `~/e2e-out` in the guest EXIT trap before any fetch. Real scenarios in `scripts/vm/real-scenarios.sh`.
- **App bug found:** `assets/mpv/live-catchup.lua` seeked to the live edge while paused (blank paused frame, no resume) and every ~1 s when the decoder/provider refills the cache faster than real time (black frames). Fix: skip while paused (re-check on resume) + 10 s seek cooldown.
- **Provider quirks (not app bugs):** first live row is a separator stream that ends after 2 s; next channel (V SPORT) bursts hundreds of seconds in 10 s then EOF. Pick the live name via E2E_REAL_LIVE. Movies open on a still card: vod-seek compares the control strip, not the picture.
- **Rejected:** frame-diff for zap (moving content changes anyway), mpv verbose log in real mode (prints URLs).
