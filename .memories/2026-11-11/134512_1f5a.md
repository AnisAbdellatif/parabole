## Parallel agents created conflicting migration numbers

- **What:** the organizing agent (stream_prefs last_name/last_logo) and the playback agent (history position_s/duration_s) both created `src/db/migration_3.sql`. The playback agent's test run opened the user's REAL DB (`~/Library/Application Support/dev.iptv-player.IPTV-Player/iptv.db`, 290k streams) and migrated it to user_version 3 with *its* migration.
- **Fix:** kept playback's file as migration_3 and moved organizing's to `migration_4.sql`. Verified on a `.backup` copy of the real DB: it reaches v4, the columns exist, and the app runs.
- **Lesson:** when several agents may add migrations, give each a pre-assigned migration number in its brief, and tell agents to set HOME explicitly (the `directories` crate falls back to the real data dir if HOME is unset).
- **State:** main includes all three gap-fix agents (organizing, sources, playback incl. embedded libmpv). 99 tests; clippy clean with and without `--no-default-features`.
